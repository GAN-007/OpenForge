# Sevi connection and remembered-key fix

The previous connection probe required its assistant reply to parse as a bare JSON object. That rejected otherwise successful responses such as prose or Markdown-fenced JSON and confused model-format validation with credential verification. It also allowed only 32 output tokens.

The probe now requests a brief plain-text reply without JSON mode, permits 512 output tokens, and requires an actual nonempty assistant response. HTTP failures, empty choices and empty/reasoning-only completions still fail. The shared OpenAI-compatible adapter accepts string content and text-part arrays, with a specific error for output-budget exhaustion. Planner and agent JSON validation remain in their existing execution paths.

After successful verification, the daemon atomically saves the key to the current user's configuration directory and activates it. Unix permissions are 0700 on the directory and 0600 on the file. Reads reject symlinks, incorrect ownership, overly permissive modes, non-regular files and oversized keys. This is a plaintext file protected by OS access permissions, not an encrypted credential vault. There is no repository-directory fallback. No credential is returned by status or stored in browser storage, project configuration or SQLite.

Daemon startup restores the saved provider without another gateway request. Connect/disconnect mutations are serialized. Failed authentication leaves the previous credential/provider unchanged. Disconnect deletes the saved key before deactivating the provider. The GUI displays remembered state and a forget-key action, and warns when connected to an older memory-only daemon.

Tests use fake keys and temporary credential directories. They cover plain/fenced replies, invalid credentials, empty responses, content-part arrays, permissions, symlinks, atomic replacement, restoration into a fresh engine, preserved credentials after a rejected replacement, deletion, and browser reload with an empty password field. Live authentication remains a user action; no real key was requested or read during debugging.
